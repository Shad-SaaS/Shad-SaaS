# PROJECT_ANALYSIS.md — وثيقة تحليل وهندسة منصة المتجر الرقمي (Digital Store Platform)

## 1. نبذة عن المشروع
منصة تجارة إلكترونية متكاملة للمنتجات والخدمات الرقمية موجهة للعملاء في الشرق الأوسط مع دعم أصيل للغة العربية (RTL)، مستوحاة من متجر `x-z.store`.
يشمل النظام:
1. **واجهة متجر للعملاء (Storefront)**: تصفح التصنيفات، شحن الألعاب، شراء الاشتراكات والبطاقات الرقمية، طلب خدمات مخصصة، محفظة إلكترونية بنظام الدفع والشحن اليدوي (Syriatel Cash, MTN Cash, Sham Cash, Crypto)، وتتبع الطلبات وتذاكر الدعم.
2. **لوحة تحكم إدارية متقدمة (`/admin`)**: مراقبة المؤشرات المالية والتشغيلية، إدارة المنتجات والباقات وحقول النماذج المخصصة، مراجعة طلبات شحن الرصيد والموافقة عليها ذرياً، معالجة الطلبات والاسترداد المالي، وإدارة العملاء والكوبونات والإعدادات.
3. **محرك المعاملات المالية الآمن**: حماية من الإنفاق المزدوج، تسجيل قيود المحفظة في دفتر أستاذ (Ledger) غير قابل للحذف، واحتساب الأسعار والخصومات في الخادم (Server-side) حصراً.

## 2. دراسة الموقع المرجعي (x-z.store)
من خلال الفحص والتحليل البرمجي للواجهة:
- **التصميم والسمات البصرية**: استخدام الوضع الليلي الفخم (Dark Mode مع لوحة ألوان كحلية عميقة `00021f` ولون أساسي أزرق كهربائي `0061fe`، وزجاجية Glassmorphism وظلال ناعمة). خط 'Tajawal' العربي.
- **الهيكل العام**: شريط علوي بارز يعرض رصيد العميل برقم الحساب، وزر شحن سريع، وشعار المتجر، وقائمة جانبية Offcanvas منسدلة.
- **التصنيفات الشائعة**:
  - شحن ألعاب (PUBG Mobile, Free Fire, Roblox, Steam...).
  - اشتراكات رقمية (Telegram Premium, Netflix, Spotify, Canva, ChatGPT...).
  - بطاقات رقمية (Google Play, iTunes, PlayStation, Razer Gold...).
  - خدمات السوشيال ميديا والتسويق (متابعون، مشاهدات، توثيق).
  - خدمات التصميم والبرمجة وحسابات الذكاء الاصطناعي.
- **وسائل الدفع الرائدة**: سيريتل كاش (Syriatel Cash)، إم تي إن كاش (MTN Cash)، شام كاش (Sham Cash)، بنك بيمو / الهرم، والعملات المشفرة (USDT). يتم الشحن عبر إرسال إشعار الدفع ورقم المعاملة وإثبات الدفع، ثم مراجعته واعتماده من الإدارة.

## 3. المتطلبات الوظيفية (Functional Requirements)

### 3.1 تجربة العميل (Customer Experience)
- **التصفح والبحث**: فلترة سريعة بالكلمات المفتاحية والتصنيفات، وبطاقات منتجات توضح الحد الأدنى للسعر والحالة والخصومات الفعلية.
- **صفحة تفاصيل الخدمة ونموذج الطلب الديناميكي**:
  - اختيار الباقة أو الفئة (Variant / Tier).
  - حقول إدخال تتغير ديناميكياً بحسب نوع الخدمة (مثل: Player ID و Server للعبة، رابط الحساب للسوشيال ميديا، بريد إلكتروني للبطاقات أو الحسابات).
  - إدخال كود الخصم (Coupon) مع التحقق الفوري وشروط الاستخدام.
  - زر طلب فوري يخصم من رصيد المحفظة بعد التأكد من كفاية الرصيد.
- **نظام المحفظة (Wallet System)**:
  - عرض الرصيد اللحظي وسجل المعاملات مع تفاصيل كل حركة (إيداع، خصم طلب، استرداد، مكافأة).
  - نموذج طلب شحن رصيد باختيار وسيلة الدفع (سيريتل، MTN، شام كاش، إلخ) وعرض بيانات الحساب المحول إليه وإرفاق رقم العملية وصورة الإشعار.
- **إدارة ومتابعة الطلبات**:
  - قائمة طلبات العميل بحالاتها: `PENDING`، `PROCESSING`، `COMPLETED`، `CANCELLED`، `PARTIAL`.
  - عرض أكواد التفعيل أو ملاحظات التنفيذ للطلبات المكتملة، وسبب الإلغاء/الاسترداد.
- **الدعم الفني (Support Tickets)**:
  - فتح تذكرة جديدة مع تحديد الموضوع والأولوية، وتبادل الرسائل مع فريق الدعم.

### 3.2 لوحة التحكم الإدارية (`/admin`)
- **لوحة المؤشرات (KPI Dashboard)**:
  - إجمالي المبيعات، الطلبات الجديدة، الطلبات قيد المعالجة، طلبات الشحن المعلقة، عدد العملاء الجدد.
  - رسم بياني للإيرادات والطلبات خلال 7 أو 30 يوماً.
- **إدارة الخدمات والتصنيفات (Catalog Management)**:
  - إضافة وتعديل وتجميد التصنيفات مع الأيقونات والترتيب.
  - إضافة الخدمات مع خيارات الباقات والأسعار وتخصيص حقول الإدخال (JSON Schema / Form Fields).
- **إدارة الطلبات (Orders Management)**:
  - تغيير حالة الطلب (`PENDING` -> `PROCESSING` -> `COMPLETED`).
  - معالجة الإلغاء مع الاسترداد الآلي للرصيد إلى محفظة العميل (Full Refund).
  - معالجة التنفيذ الجزئي مع استرداد المبلغ المتبقي (Partial Refund).
- **إدارة طلبات شحن الرصيد (Deposits Management)**:
  - فحص طلبات الشحن، معاينة إثبات الدفع ورقم الحوالة، واعتماد الشحن (مما يزيد رصيد المحفظة ذرياً) أو الرفض مع تدوين السبب.
- **إدارة العملاء والمستخدمين (Customer Management)**:
  - تعديل أرصدة المحافظ الإدارية (مع تسجيل قيد تدقيق)، تجميد وتنشيط الحسابات، وتعيين الأدوار (Admin / Customer / Support).
- **إدارة الكوبونات (Coupons)**:
  - نسبة مئوية أو مبلغ ثابت، حدود الاستخدام وتاريخ الصلاحية والحد الأدنى للطلب.
- **إعدادات المتجر ووسائل الدفع (Settings)**:
  - تخصيص اسم المتجر، العملة، شريط الإعلانات، وحسابات وسائل الدفع (رقم سيريتل كاش، رقم MTN كاش، شام كاش، إلخ).

## 4. المتطلبات غير الوظيفية (Non-Functional Requirements)
1. **الأمان وسلامة البيانات المالية**:
   - استخدام المعاملات الذرية (Database Transactions) لمنع الـ Race Conditions والإنفاق المزدوج للرصيد.
   - التحقق الصارم في جانب الخادم (Server-side validation) باستخدام Zod.
   - تشفير وحماية كلمات المرور باستخدام خوارزمية التجزئة `bcrypt`.
   - عزل صلاحيات الإدارة عبر Middleware و Session Validation.
2. **الأداء وتجربة الاستخدام**:
   - استخدام Next.js App Router لسرعة الاستجابة وتحميل الصفحات بسرعة عبر SSR/Server Components.
   - دعم كامل للشاشات المختلفة (Responsive Design) مع واجهة RTL متقنة.
3. **القابلية للصيانة والتوسع**:
   - هيكلية برمجية معيارية مع فصل طبقة الأعمال (Service Layer) عن المتحكمات (Route Handlers/Actions).
   - واجهة تكامل مجردة لمزودي الخدمات الخارجية (ServiceProviderAdapter).
