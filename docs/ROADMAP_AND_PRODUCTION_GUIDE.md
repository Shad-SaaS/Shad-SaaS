## 1. ما تم إنجازه بالكامل (Completed Milestones)

### المرحلة 0: التدقيق المعماري والتحليل الأمني
- فحص كامل الشيفرة المصدرية واكتشاف الثغرات وتحديد هيكلية المزودين السبعة وبوابات الدفع.
- توثيق الفروق الدقيقة بين مزودي التوريد الرقمي (Digital Supply) ومزودي التحصيل المالي (Payment Gateways).

### المرحلة 1: العقود الموحدة ومكتبة الأخطاء وسجل المحركات
- بناء واجهات الـ TypeScript الصارمة: SupplierDriver, NormalizedProduct, NormalizedOrderRequest, NormalizedOrderResult.
- بناء DriverRegistry كـ Singleton يدعم استدعاء المحركات ديناميكياً بدون Hardcoding.
- معجم أخطاء موحد 17 كود خطأ قياسي مصنفة بدقة:
  - retryable: هل يعاد المحاولة؟
  - safeToFailover: هل الانتقال للمزود البديل آمن ولا يكرر الشراء؟
  - shouldRefund: هل يستحق العميل استرداداً فورياً لمحفظته؟

### المرحلة 2: تشفير البيانات وقابلية الترحيل لقواعد البيانات
- تشفير AES-256-GCM للمفاتيح والرموز السرية (api_token, api_secret, pin) مع إخفاء المفاتيح عند العرض maskSecret.
- تصميم جداول Prisma لتكون محمولة 100% (Portable) ومتوافقة تماماً بين SQLite محلياً، و Neon PostgreSQL سحابياً، و MySQL عند الانتقال لسيرفر VPS.
- جداول المزودين: Provider, ProviderProduct, ProviderOrder, ProviderWebhookEvent, ProviderSyncLog.

### المرحلة 3: محركات التوريد (Supplier Drivers)
- محرك client_api_v1: يدعم منصات: Mersal, Alkasr, Alhallak, Yazancard, Tartousi, Alzaeem.
  - يدعم طرق الإرسال GET مع التحقق من الهوية عبر api-token.
  - معالجة ذكية لحقول الكميات المتغيرة (range, list, fixed).
  - معالجة أكواد الاسترجاع replay_api واستخراج أكواد الكروت الرقمية.
- محرك modc_agent: يدعم منصات Modc عبر POST و x-api-key.
  - توثيق الـ Webhooks بتوقيع آمن HMAC-SHA256 ثابت الوقت لمنع هجمات التوقيت (Timing Attacks).
- اجتياز 48/48 اختبار mock تعاقدي.

### المرحلة 4: دورة حياة الطلبات والتحويل التلقائي والاسترداد
- Dispatcher متطور (ProviderOrderDispatcher):
  - توليد order_uuid قياسي لكل محاولة لمنع تكرار الخصم (Idempotency Guard).
  - ميزة التحويل الآمن عند الفشل (Safe Failover): في حال نفاد رصيد المزود الأول، ينتقل النظام تلقائياً وبأمان إلى المزود الثاني.
  - الاسترداد المالي الذري (Atomic Wallet Refund): في حال فشل جميع المزودين، يتم إرجاع المبلغ كاملاً لمحفظة العميل داخل Transaction واحدة تضمن عدم ضياع الأموال.
  - نقطة استقبال الـ Webhook: /api/webhooks/providers/[providerId].
  - نقطة الفحص المجدول للطلبات المعلقة (Cron Sync): /api/cron/sync-orders.
- اجتياز 13/13 اختبار تكاملي.

### المرحلة 5: محرك الدفع المستقل وحماية الاحتيال (Sam API)
- محرك دفع معزول كلياً (SamApiPaymentDriver):
  - يدعم بوابات: شام كاش (ShamCash) و سيريتل كاش (Syriatel Cash).
  - فحص أرصدة المحافظ بالعملات المختلفة (SYP / USD).
  - إنشاء الفواتير اللحظية والروابط المباشرة.
  - التحقق التلقائي من عمليات الإيداع (PaymentVerificationService).
  - درع مضاد للاحتيال (Anti-Fraud / Anti-Replay): فحص فريد لكل transactionRef لمنع إعادة استخدام إشعار التحويل نفسه لشحن الرصيد مرتين.
- اجتياز 20/20 اختبار عقد وحماية احتيال.

### المرحلة 6: لوحة تحكم المزودين الديناميكية
- واجهة إدارة متكاملة في /admin/providers:
  - إضافة وتعديل المزودين مع اختيار القالب (ClientApiV1 أو ModcAgent).
  - زر فحص الاتصال اللحظي (Test Connection) للتحقق من الرصيد والاتصال فورياً.
  - جلب المنتجات المباشرة من الـ API (Sync Products).
  - ربط واستيراد المنتجات الخارجية إلى متجر شاد بضغطة زر (Import & Map).
  - عزل مزودي الدفع عن واجهة منتجات الموردين في /admin/api-products.

### واجهة المتجر وتجربة المستخدم (Storefront & Mobile UX)
- مطابقة الصور الحقيقية بدقة تامة:
  - القائمة الجانبية (Mobile Drawer) قبل تسجيل الدخول: تعرض الأزرار الترحيبية وروابط تسجيل الدخول ورابطي الرئيسية والشروط والأحكام فقط.
  - القائمة الجانبية بعد تسجيل الدخول: بطاقة العميل مع الاسم، المعرف الرقمي (مثل #1006)، الرصيد الحالي .00، أيقونات تسجيل الخروج والمفضلة، محدد العملة (USD), وكافة روابط الصفحات الـ 15+.
  - شريط التنقل السفلي (Bottom Navigation) بخمس أيقونات وتصميم عائم للرئيسية يتطابق مع تطبيقات الهواتف الحديثة.
  - عند ضغط الزائر غير المسجل على أي قسم من البطاقات بالصفحة الرئيسية، يتم توجيهه تلقائياً لصفحة تسجيل الدخول.

## 2. خارطة طريق الوصول للإنتاج وماذا يتبقى (Roadmap to Production)

### الخطوة 1: نشر المشروع وضبط المتغيرات على Vercel
المشروع مبني على إطار العمل Next.js 15 Fullstack (مع محرك Node.js وقواعد بيانات).
سبب فشل Cloudflare Worker سابقاً: أن منصة Cloudflare Workers مخصصة لـ Serverless Functions خفيفة وليست لتشغيل تطبيق Next.js مع Prisma و Node.js كامل.
الحل المعتمد والمثالي هو: نشر التطبيق على Vercel واستخدام Cloudflare كـ DNS & DDoS Protection فقط.

المتغيرات المطلوبة في لوحة تحكم Vercel (Project Settings -> Environment Variables):
1. DATABASE_URL: رابط قاعدة البيانات السحابية الحالية (مثل Neon PostgreSQL).
2. PROVIDER_ENCRYPTION_KEY: مفتاح التشفير (32 بايت Hex) لحماية مفاتيح المزودين.
3. JWT_SECRET: مفتاح تشفير جلسات تسجيل الدخول وتوكنات الأمان.
4. NEXT_PUBLIC_APP_URL: رابط المتجر المباشر (مثل https://shad-store.com).
5. CRON_SECRET: رمز حماية المهام المجدولة /api/cron/sync-orders.

### الخطوة 2: ربط النطاق (Domain) وحماية Cloudflare
عند شراء النطاق الخاص بك:
1. في لوحة Cloudflare DNS:
   - أضف سجل CNAME للنطاق الأساسي أو الفرعي يشير إلى رابط مشروعك في Vercel:
     - Type: CNAME
     - Name: @ أو store
     - Target: cname.vercel-dns.com
     - Proxy status: Proxied (البرتقالي) لتفعيل الحماية من هجمات الحجب (DDoS) والتسريع عبر الـ CDN.
2. في لوحة Vercel:
   - ادخل إلى Settings -> Domains وأضف النطاق الخاص بك، وستتم المصادقة وتوليد شهادة SSL تلقائياً خلال دقائق.

### الخطوة 3: التفعيل الفعلي للمزودين ومحافظ الدفع (Go Live)
1. الدخول للوحة التحكم /admin/providers.
2. إضافة حساباتك الحقيقية لدى المزودين (مرسال، القصر، الحلاق، يزن كارد، مودك، إلخ):
   - إدخال الـ Base URL ومفتاح الـ API.
   - الضغط على فحص الاتصال (Test Connection) للتأكد من قراءة الرصيد.
   - الضغط على مزامنة المنتجات (Sync Products) لاستيراد الفئات والأسعار وتحديد نسبة الربح الخاصة بك.
3. تفعيل بوابة الدفع Sam API:
   - إضافة مفتاح Sam API لربط حسابات ShamCash وسيريتل كاش لتبدأ المحفظة باستقبال وتأكيد الإيداعات آلياً دون أي تدخل يدوي.

### الخطوة 4: الترحيل المستقبلي لسيرفر VPS خاص (MySQL)
تم تصميم النظام بحيث تكون عملية الانتقال لسيرفر خاص خالية من أي تعقيدات برمجية:
1. تجهيز سيرفر Ubuntu/Debian مع تثبيت Node.js v20+ و MySQL 8+ و Nginx و PM2.
2. في ملف .env على السيرفر، يتم تغيير DATABASE_URL إلى رابط الـ MySQL:
   DATABASE_URL=mysql://shad_user:password@localhost:3306/shad_store
3. تنفيذ أمر ترحيل الجداول:
   npx prisma db push
4. تشغيل التطبيق عبر PM2:
   npm run build
   pm2 start npm --name shad-store -- start
